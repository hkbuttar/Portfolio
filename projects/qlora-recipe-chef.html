PROJECT 02

QLoRA Recipe Chef

Machine Learning II · Final Project Spring 2026 with Haiyang Hu, Mohan Li, Skylar Liu

Overview

A QLoRA fine-tune of Qwen2.5-1.5B-Instruct into a controllable recipe generator: given ingredients, a cuisine, and a dietary preference, the model produces a complete, correctly-formatted recipe. The reference model this builds on (Daniel-Krasik/Qwen2.5-1.5B-QLoRA-Recipe) is unconditioned; the team's contribution was adding rule-based cuisine (7 categories) and diet (vegan/vegetarian/omnivore) tags to the RecipeNLG training data and conditioning generation on them.

Approach

  • Fine-tuned with QLoRA — a 4-bit NF4-quantized frozen base plus trainable LoRA adapters (rank 16, 1.18% of parameters, 18.5M/1.55B) — on 20K examples from the RecipeNLG corpus, and measured actual training VRAM rather than citing the textbook number: 4.2GB peak vs. an estimated 30+GB (OOM on a T4) for full fine-tuning.
  • Evaluated on 5 metrics against base-model and few-shot baselines: perplexity fell 77.7% (12.20 → 2.72), ROUGE-L rose 58% (0.16 → 0.26), BERTScore improved roughly 12×, ingredient fidelity reached 0.97 vs. 0.83, and general-knowledge retention actually improved (90% → 95%), ruling out catastrophic forgetting.
  • Ran a LoRA rank ablation (r=16 vs. r=4, all else held constant): r=16 won on held-out eval loss (1.083 vs. 1.110) but r=4 was competitive, showing the method is fairly robust to rank choice in compute-constrained settings.
  • Shipped three deployment paths from the ~30MB adapter checkpoint — local PyTorch loading via PEFT, a Hugging Face Hub push with an auto-generated model card, and a Gradio web app with live base-vs-fine-tuned comparison — and reported honest limitations: dietary conditioning is weak (vegan outputs still sometimes include dairy) and cuisine tags are rule-based and occasionally noisy.
