PROJECT 07

Personal Portfolio Website

Independent Project 2026 Solo

Overview

The portfolio site you're looking at right now, rebuilt as a small but real static-site pipeline: content lives as validated YAML data, templated through Jinja2 into static HTML, tested and auto-deployed via GitHub Actions. The visual design — a hand-drawn brush-stroke motif nodding to an oil-and-charcoal painting practice — is unchanged from the original version; only the build system underneath it changed. The same schema and templates now drive three distinct content types — projects, coursework, and work experience — including recasting a project into a job-style experience entry after the fact without forking any markup.

Approach

  • Separated content from code: every project, coursework, and experience entry is its own YAML file under data/, validated against a schema (content/schema.py) that fails the build with a clear file name and reason on any malformed entry, rather than producing silently broken HTML.
  • Replaced hand-written f-string HTML generation with Jinja2 templates using proper inheritance and shared partials (nav, footer, card grid, PDF/PPTX preview cards), so a layout change propagates everywhere from one file. A single detail.html template renders all three content kinds, with small conditional differences (a "Skills" heading and location field for experience entries vs. "Tech Stack" and teammate credit for projects) driven by one kind variable rather than duplicated templates.
  • Wrote a test suite (schema validity, slug uniqueness across all three content types, link hygiene, document-folder sync) and a GitHub Actions workflow that runs the tests, builds the site, and deploys to GitHub Pages automatically on every push — verified the whole pipeline end to end, including deliberately breaking a YAML file to confirm validation actually catches it.
  • Built a document-preview system for the Links & Documents section: PDF links render as live first-page thumbnails that open in an in-page lightbox on click; PPTX links get a styled placeholder card, since browsers can't render PowerPoint natively.
  • Found and fixed a site-wide bug where every generated document link 404'd on every project, coursework, and experience detail page except the homepage résumé — the shared doc_card Jinja macro was missing the ../ path prefix that every other page-relative link in the templates already used. Fixed it by threading a depth parameter through the macro, then wrote a small audit script to verify every rendered document link across the whole generated site resolves against a real file on disk, rather than trusting a visual spot-check.
  • Grew the projects section to 19 entries via scripts/new_entry.py, including one with three links (a GitHub repo plus two separately deployed live dashboards) — confirming the schema's open-ended links: list needed no changes to support more than the usual repo-plus-one-extra pattern.
